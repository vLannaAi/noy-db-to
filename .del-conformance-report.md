## 2. Vector added

Added to `test-support/src/index.ts`, in the `edge cases` describe block, beside the existing
`empty string values` round-trip test:

```ts
it('round-trips a _del delete-marker envelope byte-identically', async () => {
  const envelope: EncryptedEnvelope = {
    _noydb: 1,
    _v: 2,
    _ts: new Date().toISOString(),
    _iv: '',
    _data: '',
    _del: true,
  }
  await adapter.put('comp1', 'coll1', 'del1', envelope)
  const result = await adapter.get('comp1', 'coll1', 'del1')
  expect(result).toEqual(envelope)
})
```

This runs against every store that calls `runStoreConformanceTests` — in this repo, that's
**only `to-browser-local`** (`to-browser-local/__tests__/conformance.test.ts` and
`obfuscate.test.ts`). Every other store uses **hand-written tests** instead of the vendored
harness (an explicitly accepted alternative per `CLAUDE.md`: "each store passes the vendored
`@noy-db/test-adapter-conformance` suite (or hand-written tests)").

Because the vendored-suite blast radius from `pnpm test` alone would only have covered
`to-browser-local` (which already passed — it stores envelopes as JSON blobs, `_del` included for
free), **I additionally audited every store's serialization code by hand** to find real droppers
regardless of test-harness choice, then added a matching hand-written `_del` round-trip test to
each store I fixed (see §4), so the fix is proven and regressions are caught going forward.

opaque bundle stores that never touch individual envelope fields, and 2 by delegating to an
already-safe sibling package.

Note: none of the 4 droppers preserved `_cek` or `_debug` either (both newer/rarer optional
envelope fields) — that's a pre-existing gap, out of scope for this pass per the task's minimal-fix

## 4. Fixes

### `to-aws-dynamo/src/index.ts`
- `itemToEnvelope()` (~line 134): added `...(item['_del'] === true && { _del: true as const })` to
  the reconstructed envelope.
- `put()`'s item builder (~line 174): added `...(envelope._del !== undefined && { _del: envelope._del })`
  to the DynamoDB item written.
- Test: added `to-aws-dynamo/__tests__/to-aws-dynamo.test.ts` (no basic put/get round-trip test
  existed for this store before — only `listPage.test.ts` and `capabilities.test.ts`) with an
  in-memory `PutCommand`/`GetCommand` mock and a `_del` round-trip assertion.

### `to-cloudflare-d1/src/index.ts`
- Schema DDL (~line 78): added `del INTEGER` column.
- `rowToEnvelope()` (~line 94): added `...(del === 1 && { _del: true as const })`.
- `upsertStatement()` (~line 112): added `del` to the `INSERT ... VALUES` column list, the
  `ON CONFLICT ... DO UPDATE SET` clause, and the `.bind(...)` args (`envelope._del ? 1 : null`).
- `listPage()`'s explicit `SELECT id, v, ts, iv, data, by, tier, elevated_by, det` (~line 236): added
  `del` to the column list. (`get`/`loadAll` already use `SELECT *`, unaffected.)
- Test: `to-cloudflare-d1/__tests__/to-cloudflare-d1.test.ts` — extended the mock's `Row` interface
  and `INSERT INTO` param destructuring to carry `del`, updated the `listPage` SQL-dispatch regex to
  match the new column, and added a `_del` round-trip test.

### `to-sqlite/src/index.ts`
- `Row` interface (~line 60) and schema DDL (~line 78): added `del INTEGER`/`del: number | null`.
- `rowToEnvelope()` (~line 100): added `...(row.del === 1 && { _del: true as const })`.
- `upsert()`'s `INSERT ... VALUES` / `ON CONFLICT ... DO UPDATE SET` / bind args (~line 131): added
  `del` column + `envelope._del ? 1 : null`.
- `listPage()`'s explicit column select (~line 224): added `del`. (`get`/`loadAll` already use
  `SELECT *`.)
- Test: `to-sqlite/__tests__/to-sqlite.test.ts` — same mock/regex updates as d1, plus a `_del`
  round-trip test.

### `to-turso/src/index.ts`
- Schema DDL (~line 61): added `del INTEGER`.
- `rowToEnvelope()` (~line 83): added `...(row.del === 1 && { _del: true as const })`.
- `upsert()` (~line 103): this store has **three** write paths sharing/duplicating SQL — all three
  fixed:
  - `envelopeArgs` shared tuple: added `envelope._del ? 1 : null`.
  - Create-only `INSERT OR IGNORE` (expectedVersion === 0): added `del` to column list.
  - Update-only `UPDATE ... WHERE v = ?`: added `del = ?` to `SET` clause and `envelope._del ? 1 : null`
    to args.
  - Unconditional upsert (`INSERT ... ON CONFLICT DO UPDATE`): added `del` to column list and
    `del = excluded.del` to the update clause.
- `saveAll()`'s inline batch-insert SQL (~line 255): same `del` column + arg addition (duplicate of
  the unconditional-upsert SQL, since `saveAll` builds its own statement rather than calling `upsert`
  when `client.batch` is available).
- `tx()`'s inline put-op SQL (~line 320): same `del` column + arg addition (another duplicate of the
  same INSERT/ON CONFLICT SQL for the batch path).
- `listPage()`'s explicit column select (~line 296): added `del`. (`get`/`loadAll` already use
  `SELECT *`.)
- Test: `to-turso/__tests__/to-turso.test.ts` — extended the mock's `Row` interface, the
  `INSERT OR IGNORE`, `UPDATE`, and `INSERT INTO` branches' param destructuring (now 12/13 positional
  args instead of 11/12), the `listPage` SQL-dispatch regex, and added a `_del` round-trip test.

No store required a STOP — every dropper's fix was mechanical (add one more column/attribute
alongside the existing `by`/`tier`/`elevated_by`/`det` pattern each store already had for other
optional envelope fields).
