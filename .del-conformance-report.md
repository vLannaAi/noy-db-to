# Full-envelope round-trip fix — noy-db-to

Date: 2026-07-09
Branch: `chore/del-conformance`

## 0. Why this supersedes the prior `_del`-only pass

The prior commit on this branch (`fix: preserve _del delete-marker across field-mapped stores`)
fixed the four field-mapped stores by adding one more named column/attribute (`del`) alongside
the existing `by`/`tier`/`elevated_by`/`det` per-field mapping. That's a **whack-a-mole** fix: it
only helps the one field someone happened to test for, and still silently drops any envelope
field the item-mapper doesn't explicitly enumerate — most importantly **`_cek`** (the wrapped
per-record content-encryption key used by `perRecordKeys`/classified-fields/blobs/`forget()`) and
**`_debug`**, neither of which the prior pass added. Losing `_cek` on round-trip makes the record
**permanently undecryptable** — a silent data-loss bug, not a cosmetic one.

This pass replaces the per-field enumeration with a **systemic fix**: each store now persists the
*entire* envelope as one opaque JSON blob (`env` column / `_env` attribute), and only keeps
`vault`/`collection`/`id` (routing) + `v` (CAS) + `ts` (ordering) as real, queryable
columns/attributes. Every current and future envelope field (`_cek`, `_debug`, `_source`,
`_sourceTs`, `_sealed`, `_vdig`, `_bidx`, …) now survives automatically — nothing to remember to
add next time hub grows a field.

## 1. The real envelope shape (confirmed from `@noy-db/hub@0.3.0-pre.7`'s `.d.ts`)

`EncryptedEnvelope` (`node_modules/.../@noy-db/hub/dist/index-BJ3L-XcV.d.ts:18995`) has far more
optional fields than the four field-mapped stores ever mapped: `_by, _source, _sourceTs, _tier,
_elevatedBy, _det, _sealed, _vdig, _bidx, _cek, _debug, _del`. None of the four stores mapped
`_source`/`_sourceTs`/`_sealed`/`_vdig`/`_bidx` either — the systemic fix closes all of these at
once, not just the two named in the task.

## 2. Per-store fix

### `to-aws-dynamo/src/index.ts`
- **New item shape**: `pk` (vault), `sk` (`{collection}#{id}`), `_v` (CAS attr,
  `ConditionExpression` on `#v`), `_ts` (kept for ordering), **`_env`** (String —
  `JSON.stringify(envelope)`, the whole envelope).
- **Legacy columns retained** (nullable, unwritten by new code): `_iv`, `_data`, `_del`.
- `itemToEnvelope()` (line ~150): `if (item['_env'] != null) return JSON.parse(env)`; else falls
  back to the old `_v/_ts/_iv/_data/_del` reconstruction (dual-read).
- `put()` (line ~185): item builder now writes only `{ pk, sk, _v, _ts, _env }` — no more
  `_noydb`/`_iv`/`_data`/`_del` attributes on new writes.
- Doc comment above `dynamo()` (line ~84) rewritten to document the new schema and the dual-read
  fallback / no-migration-needed note.

### `to-cloudflare-d1/src/index.ts`
- DDL (line ~68): added `env TEXT`; changed `iv`/`data` from `NOT NULL` to nullable (legacy-only
  now); `by/tier/elevated_by/det/del` stay nullable as before.
- `rowToEnvelope()` (line ~95): `if (row.env != null) return JSON.parse(env)`; else legacy
  reconstruction from `by/tier/elevated_by/det/del` (unchanged logic, now the fallback path).
- `upsertStatement()` (line ~121) — the **single write site** this store funnels `put`/`saveAll`/`tx`
  through: now `INSERT INTO … (vault, collection, id, v, ts, env) … ON CONFLICT … SET v=excluded.v,
  ts=excluded.ts, env=excluded.env`. Dropped the 6 legacy columns from the write.
- `listPage()`'s explicit `SELECT id, v, ts, …` (line ~241): added `env` to the column list.
  `get`/`loadAll` already use `SELECT *`, unaffected.

### `to-sqlite/src/index.ts`
- `Row` interface + DDL (line ~62/~80): added `env: string | null` / `env TEXT`; `iv`/`data`
  changed to nullable legacy columns.
- `rowToEnvelope()` (line ~112): env-first, legacy fallback (same pattern as d1).
- `upsert()` (line ~132) — **single write site** for `put`/`saveAll`/`tx`: now
  `INSERT INTO … (vault, collection, id, v, ts, env) … ON CONFLICT … SET v=excluded.v, ts=excluded.ts,
  env=excluded.env`.
- `listPage()`'s explicit column select (line ~239): added `env`.

### `to-turso/src/index.ts` — **5 SQL write sites**, all fixed
1. `upsert()` create-only path, `INSERT OR IGNORE INTO … (vault, collection, id, v, ts, env) …
   RETURNING id` (line ~134) — CAS on `expectedVersion === 0`.
2. `upsert()` update-only path, `UPDATE … SET v=?, ts=?, env=? WHERE … AND v=? RETURNING id`
   (line ~152) — CAS on `expectedVersion` match.
3. `upsert()` unconditional path, `INSERT … ON CONFLICT DO UPDATE SET v=excluded.v, ts=excluded.ts,
   env=excluded.env` (line ~172) — no version guard.
4. `saveAll()`'s inline batch-insert SQL (line ~252) — duplicates #3 for the `client.batch()` path
   (doesn't call `upsert()`).
5. `tx()`'s inline put-op SQL (line ~309) — duplicates #3 again for the batch-tx path.
- DDL (line ~67) and `rowToEnvelope()` (line ~93) got the same `env` column + dual-read fallback as
  d1/sqlite.
- `listPage()`'s explicit column select (line ~285): added `env`.

All four stores' doc comments/DDL now carry a migration note (see §4).

## 3. RED evidence — pre-fix store silently drops `_cek`

Verified by reverting the working tree to the prior commit (`git stash` back to `0864111`, the
`_del`-only fix) and running an ad-hoc round-trip test against `to-sqlite` with a `_cek`-bearing
envelope:

```
AssertionError: expected { _noydb: 1, _v: 1, …(3) } to deeply equal { _noydb: 1, _v: 1, …(4) }
- Expected
+ Received
  {
-   "_cek": "wrapped-cek-b64",
    "_data": "ct",
    ...
```

`_cek` is present on the envelope handed to `put()` but **absent entirely** from what `get()`
returns — confirming the silent-data-loss bug the task describes. (`to-aws-dynamo`,
`to-cloudflare-d1`, `to-turso` share the identical field-enumeration pattern — `_cek` was never in
any of their column/attribute lists either, pre- or post- the `_del`-only pass — so the same defect
applies to all four; sqlite was used as the representative revert-and-run since it's the simplest
mock.) Working tree was restored via `git stash pop` immediately after capturing this evidence; the
temporary test file was deleted, not committed.

## 4. Migration note (same text added as a doc comment at each store's DDL/schema site)

> New writes only populate the routing keys + `v`/`ts` + `env` (`env` = `JSON.stringify(envelope)`,
> the entire envelope). Legacy per-field columns (`iv`, `data`, `by`, `tier`, `elevated_by`, `det`,
> `del`) are retained, nullable, **only** so rows written before this change keep reading correctly
> via a dual-read fallback in `rowToEnvelope`/`itemToEnvelope` (env present → parse it; env absent →
> reconstruct from the legacy columns). No data migration script is required (pre-1.0).

## 5. Conformance vector — maximal-envelope round-trip

**`test-support/src/index.ts`** (vendored suite, `edge cases` block): added
`'round-trips a maximal envelope byte-identically (every field survives, not just _del)'`, alongside
(not replacing) the existing `_del`-only vector. Envelope carries
`_noydb, _v, _ts, _iv, _data, _by, _tier, _elevatedBy, _det, _cek, _debug, _del` with realistic
values (`_cek: 'wrapped-cek-b64'`, `_det: { email: 'abc:def' }`, `_debug: 1`, `_del: true`,
`_by: 'alice'`); asserts `toEqual` byte-identical after `put`+`get`. This suite runs for every store
using `runStoreConformanceTests` — currently `to-browser-local` only (already envelope-safe by
storing the whole thing as JSON).

**Hand-written tests** — same maximal-envelope vector added to each of the 4 fixed stores'
`__tests__/*.test.ts` (kept the existing `_del`-only and `_tier`/`_elevatedBy`/`_det` tests too):
`to-aws-dynamo/__tests__/to-aws-dynamo.test.ts`, `to-cloudflare-d1/__tests__/to-cloudflare-d1.test.ts`,
`to-sqlite/__tests__/to-sqlite.test.ts`, `to-turso/__tests__/to-turso.test.ts`. Each store's mock
(`mockClient`/`mockD1`/`mockDb`/`mockLibsql`) was rewritten to match the new 6-column write shape
(`vault, collection, id, v, ts, env`) instead of the old 11-12-column legacy shape.
